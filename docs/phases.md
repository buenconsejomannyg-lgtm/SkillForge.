# Development phases and review gates

Every phase requires an updated feature-status matrix, delivered behavior, relevant test results, known limitations, and reviewer acceptance. A planned item is not complete until its acceptance criteria are verified.

| Phase             | Deliverables                                                                                                                                            | Required acceptance/testing                                                                                                           | Known limitations and documentation                                                                                                                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 — Foundation/UI | Six responsive pages; accessible shell; profile editing; session avatar; fixed sample data; open roadmap and working checklists; local storage/recovery | Typecheck/build, validation/persistence/component tests, browser workflows, 375/768/1440px layout checks, visual review               | Local single-browser prototype; no engine, accounts, cloud, authoring, live XP, exports or publication. README and verification report describe exact working/sample/planned status.            |
| 2 — Core          | Skills/competencies, custom roadmaps, tasks, projects, XP, achievements, analytics                                                                      | CRUD persistence; progress consistency under edits/reordering; XP idempotence; analytics calculations                                 | Still browser-local. Approve XP and achievement rules before implementation; document schema changes and progression rules. XP remains separate from proficiency.                               |
| 3 — Cloud         | Supabase auth/recovery, database, user ownership, private storage, cross-device records, reviewed import                                                | Two-account isolation, direct-request policy tests, file authorization, import validation/idempotence, device persistence             | Sample data remains provisional; no public portfolio. Document migrations, policies, environment variables, backup/recovery, import consent and deployment.                                     |
| 4 — Assessment    | Approved frameworks/blueprints, reviewed banks, knowledge testing, practical rubrics, provisional evaluation, evidence/history                          | Knowledge alone cannot produce Advanced/Expert; authorized verification; reproducible versioned results; incomplete evidence handling | No implied accreditation. Review rubric, evidence thresholds, sources, verification process and overall proficiency methodology before coding scoring. Document validity limits and provenance. |
| 5 — Portfolio     | Content and certificate management, project showcase, opt-in public snapshots, approval-based updates, unpublish, portfolio PDF/resume, privacy         | Draft/public isolation, explicit selected-content approval, anonymous access tests, unpublish, PDF rendering checks                   | No custom domains or external certificate verification. Document privacy defaults, publishing workflow and certificate/export handling.                                                         |

The Phase 1 delivery is the current checkpoint. No later-phase behavior is implemented by enabling a placeholder button.
